# Ключ подписи APK

`debug.keystore` — стандартный отладочный ключ Android (`CN=Android Debug`,
алиас `androiddebugkey`, пароль `android`, отпечаток SHA-256
`FA:C6:17:45:DC:09:03:78:6F:B9:ED:E6:2A:96:2B:39:9F:73:48:F0:BB:6F:89:9B:83:32:66:75:91:03:3B:9C`).

## Зачем он лежит в репозитории

`expo prebuild --clean` каждый раз создаёт папку `android/` заново и кладёт туда
свой `debug.keystore` из шаблона `expo-template-bare-minimum`. Релизная сборка
подписывается именно им — в шаблонном `build.gradle` у `release` стоит
`signingConfig signingConfigs.debug`.

Android разрешает установку новой версии поверх старой, только если подпись
совпадает. Пока шаблон отдаёт тот же файл, всё работает; но версия шаблона —
плавающая, и при обновлении Expo SDK ключ может смениться. Тогда APK перестанет
ставиться поверх, приложение придётся удалять, а вместе с ним пропадёт весь
прогресс из AsyncStorage: пройденные темы, медали и статистика по временам.

Поэтому ключ зафиксирован здесь, а workflow копирует его в `android/app/`
после `prebuild`. Отпечаток совпадает с тем, которым подписаны все предыдущие
сборки, так что установка поверх уже стоящего приложения продолжает работать.

## Это не утечка

Файл не секретный: это общеизвестный отладочный ключ, он лежит в открытом виде
внутри шаблона Expo и React Native и одинаков у всех. Он годится для установки
APK вручную, но не для публикации в Google Play — там нужен собственный ключ,
и с ним придётся заново ставить приложение с нуля.
